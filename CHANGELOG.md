## [0.2.0] - 2026-08-31

### Added

- Optional "Built with skillskit" footer in generated repos — a shields.io provenance
  badge plus one line, below the licence, written by `create-skill-repo` by default and
  omitted with `--no-attribution`. Deliberately *not* a fourth badge in the header row
  (the three-badge cap exists to stop exactly that kind of self-dealing), deliberately
  provenance rather than a quality claim (a static image cannot assert a gate that may
  have stopped passing), and deliberately invisible to `make check` — a warning would be
  a requirement with plausible deniability, and attribution in someone else's
  MIT-licensed repo is not a quality invariant. Rationale recorded in
  `docs/readme-standard.md`.
- README standard, enforced (root + template). `docs/readme-standard.md` defines the
  shape of a skills-repo README — section order, icon first, skills-level examples
  only, demo-as-code, marked steps, the `/deslop` scope — and
  `validate_skills.py:check_readme()` enforces the mechanical half: icon and every
  local image resolving, the `npx skills add` line present, no skill-internal script
  path in any code fence, catalogue parity in both directions against `skills/`,
  step markers restricted to Required/Optional/Afterward, plus warnings for mixed
  marked/unmarked steps, missing demo media, and `<details>`/GitHub-alert syntax that
  skills.sh strips. Warnings graduate to errors once a repo ships skills, so a fresh
  scaffold reports its TODO list instead of failing.
- skillskit's own README rebuilt to that standard, with a demo-as-code GIF
  (`docs/demo/demo.tape` → `docs/demo/demo.gif`, regenerated by `vhs`) showing the
  eval gate catching a description collision: rank-1 accuracy falling 88.9% → 66.7%,
  the outranked prompts named, the build red.
- The scaffold now carries all of it: a conforming template README, and a seeded
  goal prompt that generates the icon via icon-designer-skills (candidates go to the
  human), commits a demo with its source via terminaltor/screenshooter, keeps
  examples skills-level, marks every step, and finishes with a tightly scoped
  `/deslop` pass over prose only.
- Security scanning of skill content (root + template). `validate_skills.py` now
  scans every `SKILL.md` **and every script a skill bundles** for the patterns
  registry scanners and published audits flag: a download piped into a shell, the
  environment piped into a network command, base64 decoded into a shell, and
  `shell=True` are errors; credential-path references and
  instruction-override/user-concealment phrasing are warnings. Executable badness
  errors, judgement calls warn — a noisy security gate gets ignored, which is worse
  than none. `scripts/test_validate_skills.py` asserts both halves: the malicious
  patterns still fire, and the safe lookalikes this kit uses (`env -u
  DISABLE_TELEMETRY …`, `curl … -o file`, `… | tee`) still do not. Skills bundling a
  whole repo scaffold under `assets/template/` are exempt — those files are the gate
  itself, kept honest by `check_sync.py` and code review instead.
- Ruff lint + format over the Python the kit ships (root + template): `ruff.toml`
  with `E W F I UP B C4 SIM S RUF`, `S` (flake8-bandit) being the point;
  `required-version` pins ruff so a stale one on a developer's PATH refuses to run
  rather than disagreeing with CI. `make lint` runs it through `uvx`, so no local
  install is needed. Findings were fixed, not silenced: the two `subprocess` sites
  carry `# noqa: S603` with the reason they are safe (fixed argv, no shell).
- `.pre-commit-config.yaml` (root + template) — hygiene hooks incl.
  `detect-private-key`, pinned ruff in lockstep with `requirements-dev.txt`
  (`--exit-non-zero-on-fix`, without which a fixed-but-unstaged file commits
  unfixed), workflow/dependabot schema validation, and `make check` on pre-push.
  `make hooks` installs it. Hooks are convenience; CI runs every one of the same
  checks because `--no-verify` bypasses them silently.
- `.claude/hooks/lint_python_file.py` (root + template) — PostToolUse hook running
  ruff on every `.py` an agent writes, feeding failures straight back to it. Skips
  silently when ruff is unavailable or is the wrong pinned version.
- `upgrade-repo` skill — the kit's improvements now reach repos it already
  generated. A scaffolded repo owns its files outright (its own validator,
  hooks, docs, bundled dev skills) with nothing linking it back here, so every
  earlier improvement stopped at the repos created after it.
  `scripts/upgrade_repo.py` compares a repo against the current template in two
  tiers — MANAGED files (no per-repo content) applied with `--apply`, CUSTOMIZED
  files (Makefile, CI, AGENTS.md, settings) reported as a diff and never written
  — and never touches `skills/`, the README, the CHANGELOG, `skills.sh.json` or
  the manifests. `references/upgrade-log.md` is the changelog that drives it:
  per-change Managed/Manual lists, newest first. **Maintaining it is now a repo
  convention** — a template change without a log entry reaches new repos and
  silently skips existing ones.
- `scripts/run_evals.py` (root + template) — the eval-first claim is now
  executed, not just shape-checked. Scores every trigger prompt against every
  skill description in the repo (TF-IDF cosine, stdlib only, no model call):
  fails on prompts that share no vocabulary with their description, on a sibling
  outranking a skill on its own prompt (top-K), on near-duplicate descriptions
  (routing collisions), and on a `should_not_trigger` prompt that matches better
  than every positive. `--min-rank1` is a ratchet on rank-1 accuracy; the floor
  lives in the `Makefile` (currently 85, actual 88.9%). Wired into `make evals`,
  `make check`, and CI. Deliberately honest about its limits: it is a lexical
  proxy for the router, so it cannot adjudicate near-miss negatives — those still
  need a real agent (documented in `docs/evals.md`).
- `scripts/test_run_evals.py` (root + template) — self-check for the scoring
  logic (stemming, tie-safe ranking, collision threshold, repo stays clean).
- `scripts/check_sync.py` — fails when a deliberately duplicated file drifts.
  The scaffold template's copy of the gate and the `references/` rulebook copies
  are plain files, not symlinks, and nothing compared them before: a validator
  fix applied at the top level silently never reached a scaffolded repo.
  `--fix` re-syncs.

- Codex support in-checkout: `.agents/skills/` symlinks expose the four
  skills (skill-from-research, add-skill, create-skill-repo, publish-repo)
  to Codex and other Agent-Skills-standard agents when working inside this
  repo — verified live with `codex exec`; skills.sh installs remain the
  distribution path.

- `skill-from-research` now documents the researchkit pack shape in
  `references/research-pack.md` (report.md as synthesis, materials
  frontmatter as citable primary sources, index.json fetched-only rule,
  result.json run-complete gate, subprojects recursion) — pinned to
  researchkit's `docs/research-pack.md` v1 contract.

- Initial skillskit release: create-skill-repo, add-skill, publish-repo, skill-from-research.

### Changed

- Invocation mode is now a first-class distinction (root + template). A
  user-invoked skill (`disable-model-invocation: true`) is reached by typing
  `/name` and is never routed, so the router rules never applied to it — yet the
  validator still graded it on description length, trigger clauses and negative
  triggers, and demanded 16 trigger eval cases. This repo's own `publish-repo` was
  being scored that way. Now: `validate_skills.py` applies the router rules only to
  model-invoked skills and waives the trigger-case minimums for user-invoked ones;
  `run_evals.py` excludes them from the ranking corpus entirely; `add-skill` picks
  the mode in step 1, before the description is drafted; `docs/skill-authoring.md`
  documents both styles plus the alias-over-engine pattern, and sets a 25–150 line
  body target (500 stays the ceiling).
- CI (root + template): skills CLI pin bumped to 1.5.19; consumer install test drops the `--skill '*'` wildcard; the template's skills-sh job gains a leak gate that fails when internal dev skills (add-skill/publish-repo) appear in consumer discovery.
- seed/verify install commands (publish-repo + deploying docs, root + template): dropped `--skill '*'` — the wildcard deliberately opts into internal skills; plain `add` is the consumer-faithful install.
- bundled dev skills (template add-skill/publish-repo): marked `metadata.internal: true` so skills.sh consumer installs skip them (CLI honors it; maintainers opt in with INSTALL_INTERNAL_SKILLS=1 or --include-internal); publish-repo pre-flight now asserts they stay out of `add . --list`.
- publish-repo and deploying docs (root + template): document skills.sh burst throttling — when publishing several repos, seed one at a time ~5 minutes apart (burst install events from one machine are throttled server-side; audit runs, listing never materializes).
- publish-repo (and the template's bundled copy): seamless-deploy fixes learned from a live deployment — seed installs must run with `env -u DISABLE_TELEMETRY -u DO_NOT_TRACK` (any value disables the install report, even `0`), pin `npx skills@latest` against stale npx caches, `gh` < 2.90 fallback for the release step (`gh release create` + topics), concrete listing verification (canonical page URL within minutes; badge 200 proves nothing; 404 >15 min = suppressed telemetry, not cache), and a note that agent harnesses may permission-block public-surface commands.
- validate_skills.py (root + template): validates `skills.sh.json` against the live skills.sh schema — required `groupings` with `title`/`skills`, unknown-key rejection with `groups`→`groupings`/`name`→`title` hints, size limits, cross-checks that every distributed skill sits in exactly one grouping and every reference exists.
- add-skill (root + template) and docs/deploying.md (root + template): document the exact `skills.sh.json` schema shape and the telemetry/gh-version/npx-cache gotchas in the deploy path and troubleshooting table.
- add-skill: new Measure step — delegates quality-eval runs, baseline benchmarking, and description optimization to Anthropic's official skill-creator skill (`skill-creator:skill-creator`) as a subskill when installed; the manual protocol in `references/evals.md` remains the fallback.
